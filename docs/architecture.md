# Website architecture

TanStack Start supplies server-rendered React, typed routes, and server functions. Vite builds assets and a Cloudflare Worker. Public metadata uses `https://quantum-digital.pukitis-rudolfs.workers.dev`; no deployment or domain changes have been made during local work.

## Public content and visuals

All six work stories use reusable editorial sections in `src/components/work-story.tsx`. `findPublishedWork` resolves a published record before attaching the code-managed narrative in `src/content/work-stories.ts`; related links also come only from the published collection. The page and `getCaseStudy` share this lookup. Existing saved fields remain authoritative; care, accounting, and research presentations suppress repository/demo links under the abstract-client disclosure policy, including in assistant results. Optional experience/stack labels and a bounded application-overview array describe each project independently, so accounting does not inherit finance implementation claims. No Convex schema, record migration, or admin save/publish behavior changes. The assistant tool result adds an optional validated `story` field, so older stored tool results remain valid. Supplementary stories and public illustrations are approved code/assets, not private storage: unpublication hides routes and tool results but does not erase static bundles or asset URLs.

`WorkModel` renders a poster in server HTML and imports its Three.js/GLTF runtime only after load/idle on suitable devices. A reusable asset/camera configuration matches the Blender composition and poster crop. The viewer uses WebGL2, capped pixel ratio 1.5, bounded pointer movement, demand rendering, and visibility/offscreen pause. Touch, reduced motion, Save-Data, slow connection hints, low memory, missing graphics, loading errors, a 10-second timeout, and context loss retain or restore the still. Aborted loads and unmounts dispose scene/renderer resources. Essential narrative and native disclosures work without JavaScript. Project context and delivery reuses the homepage `FaqItem` component, with semantic subsection headings and the same smooth opening/closing behavior. There is no scroll interception or database mutation from the viewer.

`src/content/site.ts` supplies approved bootstrap content and code-managed engagements, experience, and profile links. Work, services, core homepage copy, contact email, and FAQs become admin-managed after an explicit one-time content import. `shared/content.ts` validates the models, and `src/server/content.ts` loads only Convex published snapshots for public route loaders, SEO, sitemap, and assistant context. Before initialization, approved defaults are used. After initialization, empty collections stay empty and a configured backend failure fails closed rather than restoring unpublished defaults. Project descriptions come from `../interview-prep/search/portfolio.md`; identity, client-work experience, and profile links come from `../interview-prep/utils/RESUME.md`. Abstract research-workflow capabilities are checked against the implemented UI and backend in `../lead-research`. The homepage shows six examples in a horizontal row; existing portfolio routes remain available and published examples are also linked from About’s practices and current explorations. Case studies distinguish independent client work from portfolio work without claiming client outcomes, metrics, or sole authorship. Care coordination, accounting, and research examples have no external project links. See [Content decisions](content-decisions.md) for source and disclosure decisions.

Selected work uses a horizontal-section component; Services uses a normal responsive grid. On screens with sufficient viewport height, the work panel stays below the header while Motion’s scroll position moves the native row horizontally. The section’s extra height equals its horizontal travel, so scrolling releases naturally at the end and reverses when scrolling back. There are no wheel interception or body scroll locks. Reduced-motion, JavaScript-free, and short-screen layouts retain a native horizontal row with keyboard and manual scrolling.

The hero uses semantic HTML and static Q artwork before lazy enhancement. A shared WebGL fluid field drives text distortion, morphing shapes, and gold cursor sparks. Font/bounds changes resynchronize text. Supported touch screens use softer trails and localized text distortion through passive touch listeners, preserving native scrolling and crisp DOM text at rest. The fluid copy is shown only during touch interaction and restores native text as it settles. Textures are recreated after layout changes to match resized GPU storage. Graphics failure restores visible DOM text. The renderer pauses offscreen or while hidden and adapts quality. The final conversation section lazily reuses the same scene runtime in effects-only mode with its own section-sized canvas, omitting shape loading and cycling. Motion types its emphasized title once on first entry; the fluid text takes over after typing finishes. Each section pauses its renderer independently, and reduced motion keeps the complete DOM heading. Service cards use original, labeled Blender renders loaded as static JPEGs.

## Conversation and inquiries

The primary CTA and pinned header link open `/chat`, using chat-bubble icons. There is no standalone contact form and no booking integration. Vercel AI SDK streams through `/api/chat`; a configured AI Gateway key and model enable it. The assistant receives published site content plus approved public résumé and portfolio snapshots, with a compact work index and on-demand `getCaseStudy` lookups. Curated context is sufficient for the current collection; vector RAG is deferred. The chat workspace omits marketing navigation/footer and uses a compact bottom composer over the homepage hexagon pattern. `explainEngagements` returns the approved collaboration options. Safe inline links and structured reference cards let visitors move to the relevant work and service/engagement sections. See [Chat behavior](chat-behavior.md) for streaming limits and recovery.

An anonymous HttpOnly cookie, renewed for 30 days, identifies one active conversation by its server-side hash. Convex `chatThreads` and ordered `chatMessages` persist the transcript through the secret-protected Worker bridge. Saved history is authoritative, revision guards prevent stale writes after restart, and a generation lease prevents overlapping requests. The client restores messages, draft state, and receipts on return; there is no account or recent-chats sidebar. The assistant’s only intake tool prepares a validated, expiring draft in Convex. The visitor sees the exact draft and clicks confirmation. `/api/inquiries` checks same origin and the conversation cookie, then sends the draft ID and session hash to the secret-protected Convex HTTP bridge. The internal mutation checks ownership and expiry and saves the held snapshot once. Neither model text nor model tool execution can submit an inquiry.

Full transcripts expire after 30 days of inactivity and are removed by hourly cleanup. Restart deletes active messages without removing confirmed inquiries. Unconfirmed drafts expire after one hour; confirmed draft snapshots remain for at least 30 days and while their conversation stays active so saved receipts can be restored. Drafts and rate-limit records have scheduled cleanup. `requestContactDetails` opens an optional inline contact form; `/api/inquiry-drafts` prepares its held draft, and the existing explicit confirmation saves it. Cloudflare Turnstile Siteverify checks single-use tokens, hostname, and action before chat generation or inline draft preparation. Confirmed inquiries remain private in Convex. `/privacy` explains processing, storage, cookies, and contact for removal.

## Owner admin

Better Auth runs on Convex using its maintained component. Public signup is disabled. The owner is created through a key-protected setup mutation restricted to `ADMIN_OWNER_EMAIL`. `ADMIN_SETUP_KEY` must have at least 32 random characters. A database marker plus any existing auth user closes setup permanently. Password is entered twice, stored hashed by Better Auth, and no email verification/reset service is configured. Standard public signup stays disabled even during bootstrap. Lazy auth route registration allows backend deployment before auth environment configuration. Every inbox query and status mutation verifies a live session and the verified owner record on the backend. TanStack server functions forward the authenticated token; no unauthenticated caller can read inquiries or alter their status. `/admin` lists the newest 100 matching inquiries and supports `new`, `contacted`, and `closed` states.

`/admin` has dedicated Inbox, Selected work, Services, and Site settings sections, without the marketing header/footer. Explicit saves edit drafts; explicit publication copies a validated snapshot into public fields. Unpublish removes only the snapshot and keeps the draft. The website and assistant never query workspace drafts. All content mutations require the owner and an initialized workspace. Version checks reject stale saves/publication. Editors warn before discarding unsaved changes, confirm unpublication, and offer empty/search states. Approved content imports idempotently as initially published records. See [Admin workflow](admin-workflow.md).

## Configuration and release

`VITE_SITE_URL`, `VITE_CONVEX_URL`, `VITE_CONVEX_SITE_URL`, `VITE_TURNSTILE_SITE_KEY`, `VITE_POSTHOG_PROJECT_TOKEN`, and `VITE_POSTHOG_HOST` are public build-time configuration. Vite reads these six approved Wrangler `vars` as defaults; local environment files and CI build variables override them. The mapping never copies server secrets or arbitrary runtime bindings into browser assets. `TURNSTILE_SECRET_KEY` is a Worker-only secret. Only HTTPS backend endpoints and explicit loopback development URLs are accepted. Credentials belong in server bindings and the Convex environment. The intake bridge secret must match on both services. Authentication secrets never reach client assets.

The connected cloud development deployment is `peaceful-koala-818`, within the Quantum Digital project. Production and the earlier anonymous local deployment are separate. Live AI, production authentication, and production persistence require the configuration in [Inquiry setup](inquiry-setup.md). The supplied domain and portfolio content remove the previous domain/profile/content placeholders. Publishing and live end-to-end verification remain release steps.

Research and service operations narratives live in `src/content/work-exploration-stories.ts`, alongside the robotics story. Research uses six workflow steps; robotics adds four application summaries with current boundaries. Evidence separates reconstructed synthetic diagrams from existing actual simulator captures. All six stories use the same model viewer. Robotics bootstrap content includes Warehouse Demo; existing saved published fields remain authoritative and are not rewritten by this change.

About uses a full-width editorial layout, the shared `WorkModel` viewer, and its own camera/crop configuration in `src/lib/about-model-config.ts`. Approved introduction, five-part career journey, working practices, and exploration references live in `src/content/about.ts`; the assistant consumes the same introduction/journey and link-free practice descriptions. About resolves project links only from its published-content loader. Homepage layout and persisted/admin schemas remain unchanged.

Release builds use `scripts/work/build-release.mjs` and the tested public-setting guard. `pnpm build:release` takes the six public settings from Wrangler or explicit CI environment variables, overriding ignored local Vite files. It rejects local/test Turnstile keys, non-public HTTP endpoints, missing settings, and mismatched standard Convex endpoint pairs. `deploy:check` and `deploy` use this build; ordinary `build` remains available for local testing. No server secrets enter the public definitions.

`SiteAnalytics` observes client-side pathname navigation. `src/lib/analytics.ts` lazily initializes the slim PostHog SDK on public routes only after analytics consent, stores random visitor/session IDs in first-party cookies, and clears tracking cookies on withdrawal, filters events/properties before sending, and respects browser privacy signals. Chat tracks new inquiry tools while seeding restored tools as already seen. Inline draft preparation records review after validation; confirmation records attempts/results and successful submissions only after the server receipt. Analytics never changes backend writes. See [Analytics](analytics.md).
